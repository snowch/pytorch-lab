# PyTorch Lab

[Open the lab](https://snowch.github.io/pytorch-lab/)

Learn PyTorch with 26 editable lessons, including two capstone projects. Basic Python is enough to start. Each lesson has a prediction, a
working Python example with checks, a variation, and a worked explanation.

| Module | Topics |
| --- | --- |
| Tensor foundations | Shapes, indexing, broadcasting, strides, matrix multiplication |
| Autograd and optimization | Gradients, finite differences, clipping, a training step, learning-rate experiments |
| Build and train models | Modules, cross-entropy, datasets, batches, evaluation, checkpoints and resuming training |
| Vision, sequences, and attention | Convolution, a trained image classifier, embeddings, stable softmax, causal attention |
| Devices and performance | CPU/CUDA placement, synchronized timings, native CPU profiling |
| Capstone projects | Synthetic nonlinear classification and held-out next-token prediction |

## Run the exercises

The workbench runs real PyTorch in a Web Worker with an experimental downstream
Pyodide wheel. It downloads about 60 MB on first run. Code runs in the browser.
Drafts, predictions, and completion are saved in browser storage when available.
The WebAssembly runtime uses a single CPU thread. The profiling lesson collects
operator events in native Python. GPU Lab and CUDA Python Lab supply linked
kernel investigations, and the device and timing scripts can use native CUDA
when it is available.

Download the current code as Python or a Jupyter notebook from any lesson. For
a native CPU run, install PyTorch using its
[installation selector](https://pytorch.org/get-started/locally/) and run a script:

```sh
python examples/one-training-step.py
```

All datasets are generated by the included code. The capstones run on CPU
without downloading weights or datasets.

## Develop and verify

Use Node.js 24 or later and curl. The build stages pinned upstream runtime
assets and validates wheel digests, then generates the site and notebooks.
GitHub Pages serves the static build from the configured repository path.

```sh
npm ci
npm run check
npm run dev
```

Open http://localhost:4173/pytorch-lab/. The check command runs all starter
scripts against the WebAssembly runtime and compares the notebooks with their
Python source. If PyTorch is installed locally, use
`python scripts/check_native.py` to exercise the native paths.

See [third-party notices](THIRD_PARTY.md) for runtime source and license details.

## Shared course controls

The header offers Code runner, App status and theme. PyTorch stays ready between lessons until you free memory or the selected idle timeout expires (30 minutes by default). Code, predictions, results and plots are kept. App status can save and verify the complete course for offline use; normal online page loads still use the published site.

See [course style](docs/course-style.md), [managed runtime](docs/code-runner-design.md) and [offline/update design](docs/offline-update-design.md). Existing lesson URLs and saved-work keys remain stable. Runtime files are pinned to their release, with two prior verified releases retained at publication.

Run `npm run check` for all real WebAssembly examples and notebook parity. Run `npm run test:browser` for the shared controls, offline/recovery and update journeys. `npm run build` generates `dist/`; `npm run dev` serves that generated output.
